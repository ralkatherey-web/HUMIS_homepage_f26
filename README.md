### What I learned from the HUMIS project

One of the biggest things I learned from working on the HUMIS project was how to recognize patterns in a design and create reusable stylesheets that work across multiple pages. The same thing applied to images, where we noticed recurring patterns and created a separate stylesheet for them. I also became more comfortable working with CSS, especially Flexbox and positioning elements. Another thing I learned was how to organize my stylesheets based on their purpose.

I think this project was really helpful, especially if I want to create my own personal website or work on another web development project in the future. Before this project, I didn't realize how much thought and planning went into implementing a design. One example is the left column on the right-hand side of the Faculty & Staff page, where there are three main links and three subcategory links under "New Faculty." I learned to think about these elements as separate containers and use margins or padding to indent the subcategories. Even though I didn't have creative control over the design, there was still some freedom in deciding how to implement it. I think recreating an existing website was helpful because it shifted my focus from deciding how a website should look to figuring out how to implement a design efficiently.

If I were to build a website like this again, I would spend more time analyzing the original design before starting to code. I would pay closer attention to the width of different elements, padding, margins, font sizes, and the overall color palette. I would also plan out which heading tags to use for different types of titles. Another thing I would do differently is choose a more consistent approach to CSS units rather than switching between `rem` and `px`. I think having a better plan for the styles and layout from the beginning would have made my code more organized and saved me time on making adjustments.
